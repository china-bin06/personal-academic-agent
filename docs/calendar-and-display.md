# 日期课表与界面优化

## 页面

- 示例问题始终位于回答上方，折叠后不占据大块间隔。
- 顶部右侧显示北京时间，首次读取服务端时间后按单调计时器继续走时，每分钟重新同步；服务不可用时先显示浏览器换算的北京时间，并在提示中注明未同步。
- 使用用户提供的华师娘PNG，复制至static/assets，不修改原文件。桌面放在顶部右侧，窄屏排列在标题下方。滑块调节160—360px，页面保存浏览器中的图片大小偏好。

## 同步开学日期

进入独立的“开学日期同步”功能，填写当前学年、学期、第一教学周周一日期和教学周范围，点击确认并同步。本页显示当前配置及保存时间；“数据时间”页仍只展示已导入的学业数据。第一教学周周一不是报到日，不自动把周日或其他日期调整为周一。教学周范围需按校历确认，表单默认20周并在确认框中明确展示，不代表学校规定一定20周。

配置保存到本地被Git忽略的data/calendar/settings.sqlite3，按owner隔离，保存新的当前学期配置会替换该用户先前的日期配置，不修改学业数据库。无需新依赖或数据库迁移。

接口GET /api/v1/calendar返回服务端时间及当前配置，PUT保存经Pydantic校验、用户确认的配置，拒绝跨源写入。

## 问答

新增受控工具get_schedule_for_date。模型传入target_date（YYYY-MM-DD）或relative_day（今天、明天、后天）之一。

后端按Asia/Shanghai固定UTC+8获取今天，计算目标日期、星期和教学周：

`教学周 = (目标日期 - 第一教学周周一).days // 7 + 1`

仅当目标日期位于用户确认的教学周范围内才调用原get_schedule；单双周继续使用已有meeting.weeks判断，不另建课表或猜测安排。结果包含日期、学期、周次、配置更新时间及原课表来源。

未配置返回needs_configuration，超出范围返回out_of_term，并提示重新确认，而不是宣称没有课。Agent拒绝将引用这些未解析结果的最终回答设为answered。常规按周课表、成绩和培养计划工具仍然保留。

学期内没有课表快照时，沿用原“该学期尚未导入课表”提示；节假日、临时调课和补课仍不自动推断。查询实际时间仍按节次展示，尚未新增节次对应的钟点时间。
