# v0.2.0 实现与核验

## 实现思路

1. 保留第一版问答、受控查询工具、采集CLI与导入服务。
2. 使用现有解析器和Pydantic模型生成完整预览，拒绝坏文件、缺失节点和非法课表。
3. 浏览器上传原始文件字节，`X-File-Name`使用URL编码，服务器限制类型、文件大小并清理文件名。
4. 预览内容与原始文件存入本地SQLite暂存库，使用随机预览ID，不接受浏览器提交修改后的解析数据。
5. 用户明确确认后复用原PostgreSQL导入事务。SQLite立即事务串行化确认；已确认预览保存结果，重复请求返回同一结果。
6. 如果学业数据库提交成功而本地结果保存失败，重试仍由原导入服务去重。两个数据库之间没有分布式事务，页面不会在请求失败时宣称导入成功。
7. 从只读数据库连接读取成绩学期时间、课表快照、培养计划快照。按父节点展示培养计划，不重复累计学分。
8. 从最近2000行采集日志合并任务开始与结束状态，只展示允许字段，不展示HTML或认证信息。缺少结束日志时仅显示“已开始，未见结束记录”。

## 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/v1/imports/preview?data_type=grades/schedule/requirements` | 原始字节上传与预览；文件名放在X-File-Name |
| POST | `/api/v1/imports/{preview_id}/confirm` | 确认现有预览，不接收客户端解析数据 |
| GET | `/api/v1/data/status` | 数据库中的各类型数据时间与快照 |
| GET | `/api/v1/data/requirements` | 最新培养计划节点与树 |
| GET | `/api/v1/collections/tasks?limit=50` | 最近任务日志状态 |

## 核验范围

- 预览不写学业数据库；确认导入、更新、同文件去重。
- 双击、并发确认、过期预览、用户范围、坏文件、大小限制。
- 失败不泄露内部异常，失败后可重试，不把数据库失败当成空数据。
- 树的父子关系、重复节点、缺失父节点和循环关系。
- 日志合并、损坏行处理、不允许字段过滤。
- 真实PostgreSQL的ARRAY/JSONB、三类导入、数据库时间、树形结构和中途失败回滚。
- 无界面Edge操作：首页资源、预览、确认、任务状态、培养计划树、原问答澄清及窄屏布局。
- 第一版成绩解析、统计、受控工具和健康接口回归。

## 复现命令（PowerShell）

```powershell
.\.venv\Scripts\python.exe -B -m pytest tests/test_data_management.py -q
$env:RUN_POSTGRES_TESTS = "1"
.\.venv\Scripts\python.exe -B -m pytest tests/test_management_postgres.py -q
.\.venv\Scripts\python.exe -B -m pytest tests/test_management_browser.py -q
```

PostgreSQL测试需要可创建schema的本地写账号，测试创建随机`agent_v2_test_*` schema并在结束后清理，不使用local数据。
浏览器测试需要已安装的Microsoft Edge和Playwright；使用虚构接口响应，不访问学校网站或模型服务。

## 已知范围

- 仅用于绑定127.0.0.1的本地单用户部署，尚无多用户登录授权。
- 新学期PDF没有已确认参考JSON时，明确返回REFERENCE_REQUIRED；不会猜测未排课学分。
- 培养计划上传需包含完整主修树，沿用既有解析范围，不扩大到创新创业等未确认区域。
- 文件去重沿用第一版口径；PDF字节或HTML动态字段变化可能产生新快照。
- 暂存区按30分钟过期，在新上传时清理过期预览；已确认原始文件保留用于溯源。
- 第二版初始任务状态页只读取日志；后续新增了页面采集入口，见[页面自动采集](page-collection.md)。账号登录仍由用户完成。
- 不改变成绩统计规则、补考重修规则或多轮问答行为。
